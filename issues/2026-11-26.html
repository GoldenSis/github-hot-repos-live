04 R0Y00/Xbox2Windows
Summary GitHub
🔥 Hot Repos · #04
Static recompilation of Xbox Series binaries for x64 Windows
Why it matters
Static recompilation, not emulation. Instead of running Xbox code through an emulated CPU (slow, inaccurate), Xbox2Windows translates the Xbox binary's machine code to x64 at build time. The resulting binary runs natively on Windows. This approach — pioneered for N64 decomps like Super Mario 64 PC — is technically more sound than compatibility layers for many workloads. FPS backend (likely Frostbite engine integration) and GDK backend (Xbox Game Development Kit support) are noteworthy claims.
View on GitHub →
Stars
1.9k

License

Highlights
  • Static recompilation vs. emulation
    Dynamic emulation re-executes instructions at runtime; static recomp translates them once to native x64 code. The N64 PC port community (sm64, Zelda) has proven the approach works at scale. Applied to Xbox Series X/S, this is more ambitious.
  • FPS and GDK backend support
    Claiming Frostbite (EA's engine, used in FIFA, Battlefield) and GDK (Xbox's official development kit) support broadens the scope well beyond GTA VI — this could target any GDK title if it works.
  • Most technically credible approach in the wave
    Static recompilation has a track record (N64 ports), MIT license, and Python as the toolchain layer suggests serious infrastructure intent. Still early research; verify claims independently.
So what?

If this approach matures, it could produce native-performance Windows builds of any Xbox Series X/S title that gets the recomp treatment — not just GTA VI. The N64 precedent suggests it's technically viable; the Xbox Series architecture makes it substantially harder.

05 os6/nospeaker
Summary GitHub
🔥 Hot Repos · #05 · Creative hardware hack
Your MacBook trackpad is a speaker
Why it matters
Drive the MacBook's Force Touch actuator with audio signals. The trackpad uses a linear resonant actuator (LRA) for haptic feedback — the same hardware principle as a small speaker. nospeaker hijacks this actuator to play audio instead of haptic patterns. No jailbreak, no kext, pure Swift userspace. The fidelity is low (it's a haptic motor, not a speaker cone), but it technically works. Reached 1.9k stars in four days — the concept is irresistible.

    The MacBook Force Touch trackpad's LRA can vibrate at audio frequencies. nospeaker sends audio waveforms instead of haptic patterns — technically audio playback, fidelity of a 1980s PC speaker.
  • No kext, no jailbreak, pure Swift

It also hints at underexplored territory in CoreHaptics: if the LRA can do audio, what else can it do that Apple hasn't exposed through official APIs?
