01 erkamyaman/rust-anything
Summary GitHub
🔥 Hot Repos · #01
Rewrite the 20% that matters, one piece at a time
Why it matters
Gradual Rust migration with behavioral tests. Records the I/O behavior of your existing Python, Node, or Ruby functions as a test oracle, then verifies each rewritten Rust module passes those recorded tests before swapping it in. No flag days, no rewrites-of-the-rewrite.

Highlights
  • Behavioral snapshot recorder
    Wraps your existing function with a thin shim that serializes inputs and outputs to a JSON fixture file — no test harness needed.
  • Incremental swap-in
    Replace one hot path at a time; the rest of the app keeps running in its original language while fixtures keep the contract honest.
  • CI templates ship in-box
    GitHub Actions workflow included: record on main, fail the PR if the Rust port diverges from the recorded behavior.
So what?

Rust's reputation as a "rewrite everything" language keeps teams away. This flips the story: measure first, migrate the hot 20%, keep the rest. Practical for production codebases where a full rewrite is off the table.

Pragmatic performance profiling + selective Rust FFI. Profiles Python, Node, or Ruby apps, identifies the hot paths, then generates a Rust extension with an FFI wrapper for just those paths. The tagline is literal: "Don't rewrite it in Rust. Rewrite the 5% that's slow."

Highlights

  • Auto-generated FFI wrappers
    Scaffolds a Rust cdylib crate and the Python/Node/Ruby bindings in one command. You write the fast version; it handles the glue.
  • Complements rust-anything (#01)
    Where rust-anything is for gradual migration, fast-anything is for surgical performance fixes — same week, different philosophies.
So what?

Rust's FFI story has historically been painful. If this scaffolding genuinely removes the boilerplate, it could unlock performance improvements for a much wider audience of Python and Node developers.

arXiv cs.AI · Nov 2026
HabitusMem: Belief Memory over Evolving User Preferences
Introduces a persistent belief-memory module for LLM agents that tracks how a user's preferences change over time, rather than re-inferring preferences from scratch each session. Evaluated on preference-shift benchmarks where standard RAG degrades.
arxiv.org/list/cs.AI/new
NeurIPS 2026 · Multi-agent
Multi-agent Debate for Multimodal LLM Inference
Formalizes a structured debate protocol between multimodal LLM agents: agents argue competing answers over an image-text pair, with a judge agent resolving disagreements. Reports consistent accuracy gains over single-agent and ensemble baselines on MMMU and ScienceQA.
arxiv.org/list/cs.MA/current
arXiv cs.AI · Production study
Coding Agents in Production: Traces from GitHub Copilot
First large-scale characterization of coding agents using sampled GitHub Copilot traces (June–July 2026). Finds agents succeed on well-scoped tasks but fail on ambiguous specifications at much higher rates than humans, and that multi-step planning errors compound. Practical implications for agentic IDE tools.
arxiv.org/list/cs.AI/new
Lean + Claude · Math · Nov 2026
Partial Lean Proof: 67% of Riemann zeros on the critical line
A Lean 4 formalization (reportedly assisted by Claude Code) verifies that at least 67.25% of the nontrivial zeros of the Riemann zeta function lie on the critical line — up from 41.6% in prior mechanical proofs. This is not a proof of RH. The result was machine-checked but not yet peer-reviewed; the Lean community Zulip is the best place to track its status.
