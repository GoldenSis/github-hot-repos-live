SummaryGitHub
Mobile AI · On-Device Inference · Dart · Apache-2.0

Run DeepSeek on your phone. Remote-control your desktop from it.

Why it's trending

13.2k stars this week. dsh-Go is a Dart/Flutter client that lets a phone act as the AI brain for a local desktop setup: the phone runs a quantised DeepSeek model directly on the mobile NPU (or via llama.cpp bridge), exposes a tool-calling interface, and uses ADB-over-WiFi to send keystrokes, mouse events and clipboard contents back to the desktop. The result is a fully offline, zero-API-key AI assistant that keeps compute on hardware you already own. The README includes benchmarks for DeepSeek-R1-1.5B on a Snapdragon 8 Gen 3: ~18 tokens/sec at INT4.

Highlights

    Quantised DeepSeek models run directly on the phone's neural processing unit — no server, no API key, no data leaving the device.

  • ADB remote control

    The phone sends keyboard, mouse, and clipboard events to the desktop over local WiFi, turning it into a true control plane.

  • Tool-calling interface

    A minimal JSON-RPC layer lets the mobile agent trigger arbitrary commands on the desktop — file open, browser navigate, run script.

So what?

Most "mobile AI" products offload to a cloud server; this one offloads to the phone itself. For privacy-sensitive workflows — legal documents, financial data — keeping inference local on a device you physically possess is a meaningful security boundary.

Shot-by-shot video forensics: filmed or AI-generated?

Why it's trending

3.2k stars. rea-video (Reverse-Engineer-Analyse) decomposes a video into individual shots, runs a classifier on each shot's motion vectors, texture coherence, and temporal consistency, and returns a per-shot probability that the footage is AI-generated. The underlying classifier was trained on Sora, Runway, Kling, and HailuoAI outputs alongside matched camera-shot footage. Apache-2.0.

BUZZ · a16z · Nov 6, 2026 · Opinion / investor perspective
Defense in Depth, Rebuilt for Machine Speed

a16z argues that traditional defense-in-depth security architecture was designed for human-speed attacks. Machine-speed attacks — automated exploitation, AI-assisted lateral movement — can probe all defensive layers simultaneously, breaking the independence assumption that makes layered defense work. The piece calls for rethinking how security layers are composed when an adversary can enumerate all of them in parallel rather than sequentially. Opinion / investor perspective — a16z has portfolio companies in the security space.

Practical implication for builders: If your security model assumes attackers move slowly enough that your logging, alerting, and response systems can keep up, that assumption is now worth auditing. Tools like Zero-Breach-Toolkit (#04) represent the detection side of this shift — read-only, no footprint, designed to run before an attacker can adapt.

BUZZ · a16z · Nov 5, 2026 · Opinion / investor perspective
The Exploit Was the Bottleneck

The piece argues that for most of the history of offensive security, writing a reliable exploit was the hard part — requiring deep expertise and significant time. AI assistance has dramatically lowered the bar for exploit development. The bottleneck in an attack chain is now target selection and delivery, not the exploit itself. Opinion / investor perspective — a16z has portfolio companies in the security space.

Practical implication for builders: The effective attack surface has expanded because the cost to exploit a known vulnerability has dropped. This directly motivates detection-first tools — but also faster patch cycles and more aggressive asset-exposure reduction. Zero-Breach-Toolkit (#04) is the defensive complement to what this piece describes on the offensive side.
